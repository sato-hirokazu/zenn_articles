### ソフトウェアが成功する仕組み：詳細な分析

この記事は、MITのDaniel Jackson教授による「How software succeeds」の翻訳であり、ソフトウェアの成功がユーザーにとっての「成功のシナリオ」にいかに依存するかを深く掘り下げています。単に「ちゃんと動くから」という漠然としたユーザーの評価の背後にある具体的な要因を特定し、その戦略を有名な事例であるZoomとSkypeの比較を通じて示しています。

#### ソフトウェア成功の診断：Zoom対Skypeのケーススタディ

記事は、成功するソフトウェアの核心を「とにかくちゃんと動く」という体験に求め、その具体的な要素を解明しようとします。そのための主要な事例として、パンデミック中にビデオ通話市場でSkypeを圧倒したZoomの成功が取り上げられています。

**Zoomの成功シナリオ（「会議」シナリオ）:**
Zoomの成功は、その「会議」シナリオの際立ったシンプルさに集約されます。
1.  **会議の作成**: ユーザーは簡単に会議を作成し、一意のリンクを生成します。
2.  **リンクの共有**: 生成されたリンクを友人や同僚と共有します。
3.  **会議の開始**: ユーザーが会議を開始します。
4.  **参加**: 招待された側は、提供されたリンクをクリックするだけで、いつでも会議に参加できます。この際、Zoomアカウントの有無は問われません。
5.  **会議の終了**: 終了もまたシンプルです。

この一連の流れは、著者の研究仲間であるメリック・ファーストが提唱する「not not」（「〜しないわけにはいかない」）という概念を体現しています。つまり、あまりにも簡単で直感的であるため、ユーザーはこれを利用せずにはいられない、という体験を提供しているのです。特に、アカウント登録の不要さや、いつ参加しても良いという非同期性は、その敷居を大幅に下げました。

**Skypeの煩雑なシナリオ（「グループビデオ通話」シナリオ）:**
対照的に、Skypeの「グループビデオ通話」シナリオは、一見するとステップ数に大きな違いはないように見えますが、その各ステップに内在する「煩雑さ」が指摘されています。
1.  **友人の追加**: ビデオ通話を行うには、まず友人をグループに「追加」する必要があります。これは、連絡先リストから一人ずつ検索し、リストにいない場合は連絡先情報を取得して追加するという手間がかかります。さらに、友人がSkypeユーザーでない場合は招待すらできません。
2.  **通話の発信**: グループに通話を発信します。
3.  **応答**: 招待された友人は、アプリを開いているか、通話がかかってきた瞬間にその場にいる必要があり、見逃した通知を探す手間も発生します。
4.  **切断**: 通話を切断します。

記事では、もしSkypeで友人2人と話すだけであれば、この煩雑さは些細な問題でしかなかったかもしれないと認めています。しかし、パンデミックによって人々があらゆる種類の人々（友人、同僚、近所の人々など）と、より多くの人数で話す必要が生じた際に、Skypeのわずかな面倒さが「大きな障壁」となり、Zoomのシンプルなソリューションが決定的な優位性を確立したと分析しています。

#### それが全てではない：先行技術と市場の動き

もちろん、Zoomの成功が単一の要因によるものではないことも記事は指摘しています。Skypeの「ビデオ通話」シナリオからZoomの「会議」シナリオへの変遷は、一夜にして起こったわけではありません。

*   **LogMeInの影響**: Zoomの「会議リンクを事前に非同期で作成する」というアイデアは、2010年のLogMeInに起源を見出すことができます。これは、Citrixなどの既存製品よりもはるかに軽量なビデオ会議ソリューションとして登場しました。
*   **Zoomの創業**: Zoomは2012年の創業時からこのアイデアを基盤としていました。
*   **競合の追随**: 2020年にその価値が広く認識される前から、Skypeは2015年に、Googleハングアウトは1年後に同様の会議リンク機能を追加していました。

しかし、これらの競合他社による機能導入は「中途半端な形」であったと指摘されています。例えば、Skypeでは会議リンクがデフォルトの開始方法ではなく、ビデオ通話に直接リンクすることはできず、チャットからのみ開始可能でした。Skypeは2020年4月に遅ればせながら、ビデオ通話への直接リンクを可能にする「Meet Now」機能を導入しましたが、その頃にはZoomは既に市場の半分を占め、圧倒的な存在となっていました。

#### 結論

記事は、ソフトウェアが成功するためには、単に機能が揃っているだけでなく、ユーザーが直感的かつ容易に利用できる「成功のシナリオ」を中心に設計されていることが極めて重要であると結論付けています。Zoomの事例は、技術的な革新だけでなく、ユーザー体験の簡素化とアクセシビリティがいかに市場を制するかを示す強力な教訓となっています。
