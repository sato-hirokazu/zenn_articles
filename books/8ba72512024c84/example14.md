## はじめに

本章では、以下の記事をもとに、AIツールの使い分けと効果的な活用方法について整理します。

- 参考記事: https://dev.classmethod.jp/articles/ai-basics-tsukaiwake/
- 記事タイトル: 【初級向け】AIを仕事でどう使い分けているのかまとめてみた

## 1. AIの種類：対話型と自律型

AIツール（AIエージェントとも言います）を「対話型」と「自律型」の2つに分けて整理できます。

### 1.1 対話型AI（ChatGPT / Claude.ai）

- **操作する場所**: Webブラウザやアプリのチャット画面
- **やりとりの形**: 1問1答の会話
- **AIの動き方**: 聞かれたことに答える
- **得意なこと**: 相談・調査・アイデア出し
- **向いている作業**: 調べもの・壁打ち・学習

### 1.2 自律型AI（Claude Code / Kiro）

- **操作する場所**: ターミナルやIDE
- **やりとりの形**: タスクを渡して任せる
- **AIの動き方**: 自分で判断して複数ステップ実行
- **得意なこと**: 相談＋実行まで任せられる
- **向いている作業**: 実装・自動化・定型作業

### 1.3 自律型AIの特徴

自律型AIは、自分で考えて作業を進めてくれるAIです。Claude CodeなどのAIエージェントは、コーディングエージェントとも言われます。

- 対話型は「聞いたら答える」ので、次の指示は自分で出す必要があります
- 自律型は「任せたら動く」ので、途中のステップも自分で判断して進めてくれます（指示していないことを勝手に進めることもあるので注意）

## 2. 仕事での使い分け

結論から言うと、使い分けるのがベストです。「考える」ときはClaude.ai、「作る」ときはClaudeCodeを使います。

それぞれのイメージは以下の通りです。

- **ChatGPT / Claude.ai**: 人間 ⇄ AI（人間が質問を投げる単発のやりとり。出力はテキスト情報）
- **ClaudeCode**: 人間 ⇄ AI → コード/ファイル（作業のループ。出力はコードやテキストファイル）

### 2.1 具体的な使い分け例

| 作業内容 | 使うAI | 理由 |
|----------|--------|------|
| 単発の技術調査・相談 | ChatGPT / Claude.ai | さっと聞いてさっと答えが欲しい |
| 文章レビュー | ChatGPT / Claude.ai | 1回の依頼で完結する内容ならこれでOK |
| 要件に沿った細かい作業 | Claude Code / Kiro | 細かいルールを伝え複雑な作業をしたい |
| AWS検証環境の構築 | Claude Code / Kiro | 環境構築ファイルの作成や実行まで任せたい |

ここに書いているAIは一例です。他にも色々なAIを併用しています。複数のAIツールに同じことを聞いてみて、見聞を広めるみたいなこともします。

## 3. AIによって求められる人間のスキル

- **対話型（Claude.aiなど）**: 「質問力」が重要
- **自律型（Claude Codeなど）**: 「仕様を書く力」「要件定義力（決まりをちゃんと言語化する）」が重要

対話型でも、ある程度は同じ様なことができますが、自律型AIエージェントの方がもっと自由にいろんなことを任せれます。（Claude CodeならAgent Skills、Subagents、Hooksの機能など）

## 4. 並列実行の活用

### 4.1 大規模開発向け：5つ以上の並列

Claude Code開発チームのBoris Cherny氏の使い方：

- ターミナルで5つのClaudeを並列実行し、タブに1〜5の番号を振る
- システム通知でClaudeが入力待ちになったタイミングを把握している
- さらにWeb版（claude.ai/code）でも5〜10個のClaudeを同時に実行
- ローカルとWeb版を `&` や `--teleport` で行き来しながら作業している

5つのセッションを並列で動かすのは、かなり大規模なアプリケーション開発向けです。複数の機能を同時に開発したり、フロントエンド・バックエンド・テストを並行して進めるようなイメージですね。

### 4.2 普段の使い方：2つ程度の並列

開発じゃない場面では、2つ程度の並列で十分なことが多いです。

- **Claude.ai（Webブラウザ）**: ドキュメントの解釈が合っているか確認、今すぐ確認が必要な作業
- **Claude Code（ターミナル）**: AWS環境構築など、時間がかかるタスクを複数のClaudeに投げておく、バックグラウンド的な作業

並列の数は、自分の業務に合わせて決めるのがおすすめです。「1つのClaudeが考えている間に、別のことを任せる」くらいの感覚で、時間がかかる作業があれば試してみるぐらいが良いと思います。

### 4.3 ターミナルで複数のClaudeを並列実行する方法

1. ターミナルのタブを2つ開き、それぞれに番号を振る
2. 各タブで `claude` コマンドを実行して、別々のタスクを任せる
3. 裏でタスクを任せる時は、plan modeにする（Shift+Tabでモードを切り替えられます）
4. Claudeが入力待ちになったらシステム通知で知らせてもらう設定にしておく

通知設定は `/config` → Notificationsで変更できます。同じディレクトリで複数のClaudeを動かす時は、同じファイルを編集して競合が起こらないように注意してください。

## 5. 次のステップ

### ステップ1: 使い分けを意識する、並列実行を試す

「さっと聞きたい」→ ChatGPT / Claude.ai
「複雑な作業を任せたい」→ Claude Code / Kiro

まずはこの判断を意識するだけでOKです。

### ステップ2: Claude Codeの機能を使ってみる

Claude Codeには、便利な機能がたくさんあります。

- **Agent Skills**: 特定の作業手順やルールを覚えさせて、繰り返しのタスクを効率化
- **Slash Commands**: `/`で始まるコマンドで、設定変更やファイル追加などの操作を素早く実行
- **Subagents**: 複雑なタスクを分割して、別のClaudeに一部を任せる
- **Hooks**: Claudeの動作の前後に自動でスクリプトを実行

### ステップ3: 複雑な作業フローに挑戦する

紹介した使い方のように、`&`（バックグラウンド実行）や `--teleport`（セッション間の移動）を使いこなすと、より複雑な作業ができます。

## 6. AIを使わないといけないの？

（個人の感想です）

### 6.1 学習、成長のスピードが変わるから使う

最初の分からない、でつまずく時間が減ります。自分の勘違いに早く気づけるので、遠回りせずに答えや知りたいことにたどり着けるようになります。

### 6.2 調査や問題解決の切り口が広がるから使う

AIは自分では思いつかなかった視点や、そういう方法もあるのかという角度からヒントを出してくれます。

### 6.3 人がやるべき仕事が変わり始めているから使う

時間のかかる手作業を手放して、学習や確認、判断に集中する時間が増えてきた様に感じます。

## 7. AIとの付き合い方

（個人の感想です）

今は「AIに作業を任せる」「AIを使って説明する能力」だけじゃなく、「AIに適切な権限と情報、手順を与えて、自律的に動かす能力」が注目されている感じです。

これを表す言葉として「バイブコーディング」や「バイブエンジニアリング」があります。

- **バイブコーディング**: AIに任せて動けばOKとするやり方
- **バイブエンジニアリング**: 人間が仕様を決めてAIに作らせ、確認しながら進めるやり方

実際AIをちゃんと使おうとすると、全部バイブコーディング的なノリでもいける、いや全然できてない、でも昔より良くなってる…あ、全然アカンかった、みたいなことが起こります。

ClaudeCodeやKiroの新しい機能が来たら目を通したり、使えそうだったら使ったりしています。今後どんなAIエージェントが出てくるかやどんな未来が待っているか分からないので、使って慣れておくのはいいことだと思います。

## 8. まとめ

AIツールの効果的な活用には、以下のポイントが重要です。

- **使い分けの意識**: 対話型と自律型の違いを理解し、目的に応じて使い分ける
- **並列実行の活用**: 1つのAIが考えている間に別のタスクを任せる
- **段階的な学習**: ステップバイステップで機能を覚えていく
- **自律的な動かし方**: AIに適切な権限と情報、手順を与える能力を身につける
