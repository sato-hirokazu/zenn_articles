## はじめに

本章では、以下の記事をもとに、複雑なドメインを持つ新規サービス開発プロジェクトにおけるAI活用体制の構築事例を整理します。

- 参考記事: https://engineering.dena.com/blog/2026/01/ai-driven-develop/
- 記事タイトル: 育てるほど楽になる AI 開発体制を作っている話

## 1. プロジェクトの背景と課題

### 1.1 プロジェクトの特性

- 複雑なドメインを持つ新規サービス開発
- 短期間でのリリースが求められる
- 高い品質が要求される

### 1.2 AI活用状況の課題

チームにジョインした際のAI活用状況には以下の課題がありました。

- AIの活用方法がメンバーによってバラバラ
- AI生成コードの品質にばらつきがある
- レビュー工数が依然として高い
- AIへの指示（プロンプト）の質に依存している

## 2. 設計方針：2つの軸

これらの課題に対し、やみくもにツールを導入するのではなく、以下の2つの軸をベースにワークフローを設計しました。

### 2.1 レビュー作業の量を減らす

人間が見るべきは「ビジネスロジックの正しさ」や「アーキテクチャの妥当性」といった本質的な部分です。コーディング規約違反、単純なバグ、タイpoといった機械的なチェックはAIによる一次レビューで完結させ、人間がレビューする時点でノイズが除去されている状態を目指しました。

### 2.2 開発成果物の品質を標準化する

チームメンバー全員が品質の高い成果物を高速に出力できる状態を目指しました。コーディング規約、設計パターン、ドメイン知識などをAIが参照できる形で整備することで、経験やスキルに依存せず、誰でも一定水準以上のコードを素早く生成できる環境を目指しました。

## 3. 構築したアーキテクチャ

この指針に基づき、以下のアーキテクチャを構築しました。

### 3.1 コンテキストの一元管理

AIを単なる「汎用的なアシスタント」ではなく、「プロジェクトの文脈を知り尽くしたメンバー」にするため、ドキュメントやガイドラインを整備しコンテキストを一元管理する構成にしました。

リポジトリには、AIが参照するコンテキスト情報を集約しています。docs/や設定ファイルを更新すれば、AIの出力精度も向上する仕組みです。

### 3.2 3つのフェーズでのAI活用

チームでは、以下の3つのフェーズでAIを活用したワークフローを構築しています。

1. **開発フェーズ**: 開発者がローカル環境でAIを活用して実装
2. **レビューフェーズ**: PRが作成されると、Claude Code Actionsが自動レビューを実行
3. **改善フェーズ**: レビューでの指摘をドキュメントに反映し、AIの出力品質を継続的に向上

## 4. 効果の高かった4つの取り組み

### 4.1 サブエージェントの活用

すべてのコンテキストをメインエージェントに渡すと、コンテキストが肥大化し汚染されてしまいます。そこで、特定のタスクに特化したサブエージェントを作成しました。

**作成したサブエージェントの例**:
- APIレビュー専門エージェント
- セキュリティチェック専門エージェント
- パフォーマンステスト専門エージェント

### 4.2 Claude Code Actionsによる自動レビュー

整備したサブエージェントを利用してレビューを行うワークフロー（GitHub Actions）を作成しました。

実際にClaude Code ActionsがPRに対してレビューを行った結果：
- 重要度ラベル付きで具体的な指摘が入る
- 人間はガイドライン違反などのチェックから解放される
- 本質的な設計やロジックのレビューに集中できる

### 4.3 LSPを活用したMCPサーバーの導入

ローカル開発においてAIの精度を高めるため、LSP（Language Server Protocol）を活用したMCPサーバーを導入しました。

**課題**: モノレポのような巨大なコードベースでは、単純なファイル検索だけではAIが必要なコンテキストを見つけるのに時間がかかったり、必要な情報を見つけることができず精度の低い回答や実装をすることがありました。

**解決**: Serenaを導入したことで、AIがコードのシンボルや依存関係などを正確に把握できるようになり、アウトプットの速度・品質が向上しました。

### 4.4 レビュー指摘のナレッジ化

人によるレビューでの指摘事項を確実にナレッジ化する仕組みを作成しました。

**フロー**:
1. レビューで指摘事項が発生
2. 指摘事項をドキュメントに反映
3. AIがドキュメントを参照して出力品質向上

このフローにより、「レビュー → ドキュメント更新 → AIの出力品質向上」というサイクルが回るようになりました。

## 5. 得られた効果

これらの工夫により、以下のような効果が得られました。

- **レビュー工数の削減**: 機械的なチェックがAIに任せることで、人間のレビュー時間が大幅に削減
- **品質の標準化**: AIが常に一定水準以上のコードを生成するため、成果物の品質が安定
- **開発速度の向上**: AIの精度向上により、実装からレビューまでのサイクルが高速化
- **チーム全体の生産性向上**: 経験やスキルに依存せず、誰でも高品質なコードを生成可能に

## 6. 今後の展開

本記事では設計・実装・レビューフェーズでのAI活用を紹介しましたが、最近ではチーム内のビジネス職メンバーやPdM（プロダクトマネージャー）などもCursorを使い始めており、仕様策定や書類内容の確認といった業務にも活用が広がっています。

こうした上流工程は人手がかかる一方で、ビジネスインパクトが大きい領域です。仕様の抜け漏れ検出や要件整理などをAIで効率化できれば、チーム全体の生産性向上につながります。エンジニアに限らず、職種を超えてビジネス価値に直結するAIとの協働体制を築いていきたいと考えています。

## 7. まとめ

本記事で紹介した、AIを活用した開発の仕組みづくりのポイントは以下の3つです。

1. **コンテキストの整備**: AIをプロジェクトの文脈を知り尽くしたメンバーにするため、ドキュメントやガイドラインを整備
2. **自動化の推進**: 機械的なチェックはAIに任せ、人間は本質的な部分に集中
3. **継続的改善**: レビュー指摘をドキュメントに反映し、AIの出力品質を継続的に向上

AIを個人の補助ツールにとどめず、チーム全体で活かすには、プロジェクト固有のコンテキストをどう整備・共有するかがポイントになります。

育てるほど楽になるAI開発体制を築くことで、複雑なドメインを持つ新規サービス開発においても、スピードと品質を両立した開発が可能になります。
