## はじめに

## 1. 前提

昨年は会社で使っているSaaSサービスからMarkdownファイルを生成するツールを複数作成していました。この他にも、Amazon SNSへ送信するメール本文整形LambdaをClaude Codeと一緒に作成しました。

## 2. Skills

Skillsは非常に有用な機能です。

### 2.1 Skillsの活用

最近は「会社で使っているSaaSサービスからMarkdownファイルを生成するツール」を作成していますが、これをSkill化しました。

作成にあたってはAnthropics公式の `skill-creator` を使用しました。

### 2.2 開発後の振り返り

新しいCLIツールを開発したときは、最後に振り返りをお願いして、Skillを改善できるか検討しています。

まだ「スラッシュコマンドと何が違うのか」は分かっていないですが、現状での不満はなく、後述のdigで仕様が固まれば、開発は放置で進むようになりました。

## 3. dig（仕様書の深掘りQAスラッシュコマンド）

Kuuさんが作成したSlash Commandを活用しています。ファイルを見て質問してくれ、それを元に確定事項を追加してくれるので、非常に便利です。

### 3.1 具体的な進め方

以下のように進めています。

1. **SPEC.md（仕様書）を作成する**: 自分が思いつく範疇を、ざっくり記載で十分
2. **`/dig` で SPEC.md を解析**: 不明点を質問してもらう
3. **選択肢の中からカーソルキーで選択するか、自由入力欄で回答する**
4. **回答が貯まったらClaudeが SPEC.md を修正**: 修正内容を確認する
5. **自分が満足いくまで、2-4を繰り返す**

このプロセスにより、仕様の抜け漏れを事前に防ぐことができます。

## 4. 関数単位のドキュメントリンク

これはLambda開発のときに使ったテクニックです。Xで見つけたものを活用しています。

### 4.1 実装方法

コメント行で、ドキュメントのPathをいれておくと、機能修正の際にClaudeがドキュメントを参照してくれる可能性が高まります。

以下のような感じです。

```python
def lambda_handler(event: Dict[str, Any], context: Any) -> Dict[str, Any]:
    # docs/lambda_handler.md
    """
    メインのLambda関数ハンドラー
    XXXXXのSNSイベントを受信し、Email/Chatbotに転送する
    """
    # 以下、関数の実装
```

### 4.2 CLAUDE.mdでの指示

CLAUDE.mdにも、これを守るように指示を入れています。これにより、Claudeがコードを参照する際に、関連するドキュメントも一緒に参照するようになります。

## 6. まとめ

本記事で紹介したClaude Code開発テクニックのポイントは以下の通りです。

1. **Skillsの活用**: 繰り返し行うタスクはSkill化して効率化
2. **digコマンド**: 仕様書の深掘りQAで仕様の抜け漏れを防止
3. **関数単位のドキュメントリンク**: コメント行にドキュメントPathを記載し、Claudeが参照しやすいようにする

これらのテクニックを活用することで、より効率的なAI駆動開発が可能になります。
